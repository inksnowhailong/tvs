国内很多公司，很多项目，都会既要又要
相同业务想在**pc**，**小程序**，**APP**中同时拥有一席之地。
所以，我们开发了**turbo-vertical-space**，一个架构好的多端项目的基础工程框架。
- 它**不是**vue,react,uniapp等那种强大的底层框架， **而是**进行了架构设计后，选取了目前最先进流行的技术栈，组建了一个开箱即开发的基础工程

## 核心架构逻辑

*业务、技术底座、平台适配与 UI 分离，一套稳定业务能力服务多个端。*

本工程现在采用四层结构：

- **core**：业务核心层，只存放业务事实、业务规则、业务契约和纯业务能力。
- **infrastructure**：基础设施层，存放 request 抽象、store 引擎、持久化、缓存、日志等技术底座。
- **adapters**：平台适配层，存放 axios、uni.request、Vue、React、样式资源等具体平台或框架绑定。
- **views**：端侧视图层，存放 PC、App、小程序等具体端的页面、组件、路由入口、布局和 UI 交互。

核心判断：

```text
业务是什么、业务如何流转 -> core
技术机制如何组织 -> infrastructure
当前平台如何实现某个能力 -> adapters
用户如何看到和操作 -> views
```

项目已接入 Cursor 架构治理配置：

- `.cursor/rules/**`：约束 AI 按新分层写代码。
- `.cursor/agents/project-architecture-governor.md`：架构守护子 Agent，不负责记忆维护。
- `.cursor/hooks.json`：在会话结束时做轻量架构边界检查。
- `docs/AI项目架构与记忆治理方案.md`：完整治理方案原文。
